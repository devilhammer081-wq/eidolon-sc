# Spec: 外出系统

Status: ready-for-agent

左侧导航新增「外出」（对话/朋友圈/玩法/设置之后）。两种进入方式：玩法页的「外出」卡片带参进入（选 1–3 位小偶像同行）；直接点导航「外出」是制作人独自外出。

## 决定（已与用户确认）

- 同行上限 3 人；地点首批：电影院、商场、游乐场、海边。
- 独自外出：纯散步见闻 1–2 段话即结束；另有概率偶遇偶像，偶遇后偶像按当前场景主动发起话题（类似对话）。
- 制作人发言的回应规则与群聊一致：不 @ 时随机 1–2 位同行角色回应；@ 某角色仅其回复（@ 解析这里也要做，群聊复用）。
- 首版不做每日次数限制；地点素材已由用户生成（`.scratch/temp/20261113/{cinema,mall,amusement-park,seaside}.png`），实现时拷入 `frontend/public/outings/`。
- 多角色回合引擎是本功能建的可复用接缝：功能二（283事务所群聊）之后直接复用，不再另起一套。

## 行为

### 独自外出
- 入口选「独自外出」→ 随机地点（或用户可选地点，v1 随机即可）→ 生成 1–2 段散步见闻展示；结束。
- 见闻生成后有概率（LiveConfig 可调，默认如 30%）偶遇一位偶像：按好感度与该地点偏好（characters.toml 的 `place_likes`）加权抽取；偶遇后进入类对话会话，她的开场白由 LLM 按场景（地点见闻 + 她的人设 + 当前关系档位）主动生成；之后就是普通 1:1 对话回合（复用现有 engine 的 turn 管线）。

### 同行外出（经玩法页）
- 选人（1–3）→ 选地点 → 进入外出会话：开场由 LLM 生成场景描写 + 各角色到场反应（按人设与好感档位）。
- 制作人可说话/行动推进；也可触发地点事件（事件池按地点配置，如电影院「选片争执」、海边「浪打过来」）；角色之间会互相搭话。
- 结束（用户主动结束，或事件自然收尾）：好感度结算——按地点偏好 + 事件走向，走现有 affinity 链路；同行记忆写入现有跨角色共享记忆（memory.py），同行的她们事后都记得。
- 外出会话里的互动动作（功能一）v1 不接入，留到之后。

## 技术方案（接缝）

- 后端新模块 `outings.py` + store 新表：outing（id、user_id、地点、参与角色、状态 opening/ongoing/ended、时间）、外出消息（说话者角色 id、文本、事件标记）。多角色消息表设计要考虑群聊复用（speaker_id 可空表示制作人）。
- `group_turns.py`（暂名，多角色回合引擎）：输入（会话消息历史、候选说话人、各角色人设/好感/相互关系），职责＝选谁回应（权重：与制作人的好感 + 与已发言角色的关系，moments.py 的 `relations()` 已有关系图）+ 组装多角色 prompt + 产出下一条消息。群聊与外出会话共用。
- 事件池：地点目录 `characters/outings.toml`（场景描述、事件列表、好感倾向），风格对齐 `characters/gifts.toml`。
- API：`POST /api/outings/solo`、`POST /api/outings`（发起同行）、`GET /api/outings`（历史）、`POST /api/outings/{id}/turns`（同行会话回合）、`POST /api/outings/{id}/events`（触发事件）、`POST /api/outings/{id}/end`。
- 前端：`AppNav.tsx` + `i18n/zh.ts` nav 加「外出」；新路由 `(nav)/outings/`：入口页、选人页、会话页（多角色气泡 + 地点头图）；玩法页 `playCards` 加卡片。偶遇的 1:1 会话直接复用现有对话页组件形态。
- 设置：偶遇概率、回应人数等进 `live_config.py`。

## Testing Decisions

- 后端：pytest——地点目录加载、偶遇加权抽取、多角色选人权重、外出回合 HTTP 流（mock LLM，仿 test_interactions）、结算写记忆。
- 前端：typecheck + vitest；选人上限、导航项、卡片入口。

## 验收

- 导航出现「外出」；玩法页有「外出」卡片。
- 独自外出产出 1–2 段见闻；有概率偶遇并进入她主动开场的对话。
- 选 1–3 人同行进入会话：制作人说话随机 1–2 人回应、@ 只让被 @ 者回；事件可触发；结束后好感变化、记忆落库。
- 地点四张图在选地页/会话头图展示。
